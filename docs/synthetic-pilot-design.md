# 合成拉伸视频微调可行性试点设计

状态：**逐类原型实施中**。高层目标和 88=70+18 的边界已确认；金属脆性标距内 v0.5 单条视频已完成不规则断口、断后停机和生成端 QA，详见 [synthetic_0002 报告](qa-synthetic_0002.md)。下表的逐类数量仍是初版配额，未完成的语义、参考与接入门禁不能被视为已通过。

## 目标与已知事实

只比较同一未微调基座模型与使用本批模拟视频微调后的模型，在**相同真实视频、采样、Prompt、生成参数与 V4.1 严格评分**下的识别表现。微调使用两个训练随机种子，合成验证集只用于选择 checkpoint；真实对照评测在选择完成后执行。主结果是四字段联合正确率，辅以各字段逐类表现、类别等权汇总、契约合法率和明显类别退化检查。判定阈值在真实评测样本规模与基座结果核实后、任何合成训练开始前冻结。一次 88 条源视频的试点只能筛选方向。

本机历史真实数据的 `mVllm/data/03_splits/stratified_test_split.json` 恰好含 **88 条 development / 22 条 test**；这是源视频数量，不是每折训练量，也不是子视频数。历史 development CSV 含金属 42、复材 31、高分子 12、其他 3；断裂模式含韧性 39、脆性 17、界面脱粘 6、爆炸性 1、未断裂 5、视频异常 12 和齐根/组合 8，**没有明确标为半脆半韧或未夹紧的 development 源**。原始 MP4、CSV 和旧划分在本机 `../mVllm/data/` 可只读核查；当前 `mVllm_2` 的正式数据发布在训练机，不能把旧目录直接当成当前正式训练 release。陶瓷也不是该历史 development CSV 的独立材料类别，只有一个“其他(无机非)”视频且标为异常；首批是否需要陶瓷取决于新增开发参考，不从名称推断其断裂行为。

`video_0006` 与 `video_0041` 的断后分离在全幅参考帧中清楚；其余几类不能仅凭历史标签和稀疏接触表判定机制。`video_0005` 在 29.0–29.5 秒仍连续，随后镜头移走，最初接触表末帧的白区不能解释为断裂；`video_0021` 的抽样帧也连续，但两条源的 CSV 都标为异常，因此正常未断裂仍缺合格参考。`video_0034` 的试样在人员遮挡后消失，不能据此重标为材料断裂或当作普通断裂原型。`video_0008`、`video_0025` 尚须核实 development 身份与画面。这个表覆盖每个可可靠表现的 V4.1 枚举值，**不执行机制 × 位置的笛卡尔积**。材料类别以本机真实 development 的金属、复材、高分子为首批主要分布；同一材料可以承担不同机制，同一机制尽量跨材料，不能让模型只凭材质或场景颜色猜标签。对于无法找到非测试参考或无法清楚表现的家族，配额保留为待决，不用近义标签或模糊画面补数。初版配额不是统计功效保证；18 条合成验证中的稀有类只有 1–2 条，仅支持选模，不支持可靠的逐类结论。

每条完整视频只渲染一套独立的材料与行为配置。变化重点是材料大类、试样合理外形、局部变形的位置/幅度、断裂时刻/位置与断后运动。正常视频固定主要灯光和视角，首批不以换材质颜色或大幅移动相机充数。暂不增加 `trajectory_id`；生成记录需要检查不同配置确有独立轨迹，同一源视频的全部窗口始终保持同一划分。

## 视频级标签与画面门禁

现有十字段 `synthetic-tensile-video/v0.1` 只对已实现的正常韧性断裂样本完成验证；不能直接声称它已定义未断裂、未夹紧和视频异常的全部含义。拟保持简洁的同名 JSON，不放入 `clip_state`、切片区间或训练格式。正常断裂使用 `has_fracture=true`、首次完全分离时间、契约原词机制和位置；正常未断裂使用 `has_fracture=false`，时间/机制/位置为 `null`；未夹紧与视频异常都必须让后续窗口成为 V4.1 `无法判断`，机制和位置为 `null`。**视频异常是否允许 `has_fracture=null` 作为“断裂有无未知”需要在扩展侧车 schema 前确认**；新语义应以新 schema 版本承载，不悄悄改变既有 v0.1 定义。

原型 QA 必须分别验证：材料与夹具关系；变化过程足以区分机制；断口与标距/肩部/夹具口的位置关系；断前最后可靠帧连续、首次断离帧分离；窗口实际采样仍能看见这些证据；视频和标签同步；同配置/种子重建无时刻漂移。`临界未断裂`只从可见局部前兆判定，且依 V4.1 只允许韧性断裂或 `null`。视频异常家族不能把仍可清楚判断的轻微手持抖动标成异常。每个家族至少完成原型关键状态和正式编码后回读，再进入批量渲染。

## 真实／模拟双源入口

在 `mVllm_2` 的现行 `versioning data` 源阶段增加**显式模拟源读取器**；真实源的现行 `tensile-data/inputs/v1` 和 CSV 逻辑保持原样。模拟源读取器逐对读取完整 MP4 与同名 JSON，校验 schema、字段关系、契约枚举、同名、唯一 ID、媒体时间线与断裂帧，保存原始侧车和媒体摘要；规范化为当前下游可消费的视频级记录。数据来源类型应显式声明并进入发布身份，不靠文件名猜。保留 `synthetic_XXXX` 源 ID，不为适配当前 `video_\d{4}` 校验而静默改名；需要同步审计候选、ROI、媒体、发布、训练与评测链中对 ID 格式的假设。最小实现先用 `synthetic_0001` 在隔离 store 走通 source → ROI → subvideo → review → release_validate，真实 `v1` 输入另做回归核对。

当前候选规划器会跳过未夹紧和视频异常源；要覆盖这两类，数据链路需在已确认的 V4.1 语义下产生、物化并人工审查可见的 `无法判断` 窗口。源视频最终会断裂，也不能把机制和位置复制给其早期普通未断裂窗口。候选窗口与 8 帧实际采样的标签由同一规则及人工审查确定，不由 Blender 写入单视频 manifest。

现行 `versioning train` 固定三折，正式 `versioning eval` 固定已注册模型、validation 全量评测；本试点是 70/18 单次合成训练/验证划分、两个 seed、未微调基座对照、并须排除真实参考源。因而接入验证还需明确补齐**单次训练试验、基座模型评测、真实评测子集冻结**三个能力，或在版本化工作流内提供等价且可审计的适配；不能冒用三折身份、把参考源留在真实评测中，或绕过媒体/模型摘要。此处是独立于侧车入口的第二组工程缺口。

## 评测与执行门禁

已查看的历史 development 源记录在 `configs/pilot_reference_registry.json`；即使某条后来未被选作原型参考，只要画面被查看过，也须在映射到正式发布身份后从真实评测集排除其同源片段。该登记表只证明历史 split 身份，不证明本机媒体与训练机正式 release 相同。历史 sealed test 已使用过，不用于本试点反复挑方案。基座模型与两次微调模型使用相同冻结真实视频窗口、实际采样、Prompt、生成参数和严格评分器。先冻结素材、来源、评测集合与判定规则，再执行训练；基座结果可用于在训练前确定数值门槛，但之后不得按真实评测反馈迭代视频生成或挑 checkpoint。

执行门禁按顺序为：

1. 本设计与视频级异常语义确认；登记 development 真实参考与排除集。
2. 每个家族完成视觉原型、同名 JSON 与独立 QA；缺少参考的家族单独待决。
3. 模拟源入口以单视频在隔离 store 走通，并证明真实 CSV 入口行为未变；特殊情况窗口能进入发布。
4. 批量 88 条完整视频，逐条通过技术和视觉 QA；按原型家族与源视频身份冻结 70/18，核对窗口分布。
5. 冻结同一基座、Prompt、真实评测集、阈值、训练配置和两种 seed；只用合成验证选 checkpoint。
6. 对基座及两次微调模型作同条件真实评测，分别报告四字段联合正确率、逐类识别、契约合法率、类别坍缩和失败样例；结论只判断是否值得继续投入。
