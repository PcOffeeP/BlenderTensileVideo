# Blender 拉伸视频 MVP

## 1. 目标与当前状态

本项目用 Blender 生成标签同步、可复现的材料拉伸视频，为模型学习连续性、颈缩、断裂模式和断裂位置提供候选视觉样本。当前 MVP 只制作并完善一条 Golden Prototype：**金属扁平哑铃形试样、韧性断裂、标距内断裂、正常清晰视频**。

[整体生成任务书](phase-1-task.md) 独立保留，规定生成目标、标签语义、交付边界及阶段要求，后续工作继续以其明确决定为依据。本文在该任务书约束下整合当前 MVP 的场景规格、实施细节和过程总结，不替代整体任务书，也不把当前 MVP 的局部实现扩大为后续所有阶段的固定方案。具体运行命令见 [README](../README.md)，首条视频的逐项证据见 [QA 报告](qa-synthetic_0001.md)。

| 事项 | 当前状态 |
| --- | --- |
| 场景、动画、完整 MP4 与同名 JSON | 已实现，原型基线提交 `47ae906` |
| 视频规格、标签、断裂时刻、几何连续性与构图 | 单视频 QA 及独立复核通过 |
| 确定性复现 | 场景和关键几何重建已验证；未验证两次完整编码字节一致 |
| 金属断裂的动态观感 | 用户认可基本视觉语义，但认为断裂观感偏高分子；修正方向已确认，尚未实施 |
| 下游直接读取视频级 JSON | 尚未完成接入验证 |
| 加入合成视频后的微调收益 | 尚未验证 |

完成这一条原型后停止，不直接进入大规模生成或扩展参数系统。优先保证视觉过程清楚、标签时间准确、脚本可复现，并为后续扩展保留实现空间；不追求有限元级力学真实性。

## 2. 冻结范围与工作原则

- 当前只支持金属扁平哑铃形、`韧性断裂`、`inside_gauge`、`special_case=null`。
- 不制作脆性断裂、界面脱粘、爆炸性断裂或其他类别；首版无抖动和模糊，不加入遮挡等异常。
- 不使用圆棒、纤维束、薄膜或复杂复合材料替换试样；不自行改变试验机等级、相机角度、背景样式、材质颜色或夹具结构。
- 不修改现有数据处理链路，不在生成端输出子视频、采样帧、V4.1 训练样本或训练 release；不只交付 `.blend`。
- 不使用导致断裂时刻不可控的随机物理模拟。

普通实现缺口由 Agent 自主处理并记录必要理由，包括网格密度、材质节点实现、局部位移函数和渲染兼容配置；不得把这些选择扩大为冻结方案变更。文档直接冲突、缺失信息改变标签语义或使验收无法判断、Blender MCP 或渲染环境无法完成必要操作时，暂停依赖该问题的工作并说明证据；不受影响的部分继续。

## 3. 试样、夹具与场景

### 3.1 试样几何

模板为 `flat_dogbone_v1`。采用归一化尺寸，不绑定具体 ASTM/ISO 标准。

| 参数 | 冻结值 |
| --- | --- |
| 标距段宽度 W | 1.0 |
| 标距段长度 | 4.0W |
| 夹持段宽度 | 1.8W |
| 单侧夹持段长度 | 1.5W |
| 试样厚度 | 0.15W |
| 肩部过渡圆角半径 | 0.8W |

试样中心轴与 Blender Z 轴重合；沿轴依次可辨上夹持段、上夹具根部、肩部、标距段、肩部、下夹具根部和下夹持段。标距与肩部网格加密；初始连续，无裂缝和错误穿模。夹具仅遮挡夹持段，不能遮住整个根部或肩部。

这些区域支撑契约中的 `inside_gauge`、`outside_gauge_non_root` 和 `grip_root` 区分；当前仅实现前者，不因此扩展其他位置样本。

### 3.2 试验机

采用 **L1：上下夹具与上下局部横梁**，至少包含 `Grip_Upper`、`Grip_Lower`、`Crosshead_Upper_Partial`、`Crosshead_Lower_Partial`。当前夹具为成对夹爪，应清楚显示试样进入位置、夹具口和根部，且上下同轴。

下夹具固定，上夹具沿 Z 轴移动，上局部横梁与其一致运动。上下夹持端始终跟随对应夹具，禁止滑脱。试样肩部与标距保持连续。

不增加完整机架、立柱、保护罩、控制面板、显示器、品牌文字、液压管路、大量螺栓、力—位移曲线及其他实验室装饰。夹具是位置判断的必要证据，完整设备则会占用画面并引入无关背景特征。

### 3.3 材质、背景与灯光

试样材质模板为 `neutral_brushed_metal_v1`：中性灰、轻微金属反射，无强高光。原设计的建议初值如下，属于外观调节起点，不代表真实材料本构：

```json
{
  "base_color": [0.45, 0.45, 0.45, 1.0],
  "metallic": 0.8,
  "roughness": 0.5,
  "anisotropic": 0.1
}
```

不得以材质节点推导断裂机制；行为由动画控制。禁止镜面反射掩盖颈缩和断口，禁止用鲜艳颜色区分类别或建立颜色与标签的固定绑定。首版不加锈蚀、涂层、划痕或复杂纹理。

背景为浅灰或中性灰，无纹理干扰，覆盖完整视场；固定柔光和曝光维持试样与背景的稳定轮廓对比。不得出现背景卡边缘、过曝或使关键区域难以观察的亮度变化。

### 3.4 相机与构图

相机模板为 `front_fixed_v1`：正面，光轴基本垂直于试样正面，全程禁止移动、缩放或旋转。

- 上下夹具同时完整可见；“夹具—试样—夹具”整体占画面高度约 75%–85%。
- 标距段占画面高度约 30%–45%；试样中心与画面中心偏差不超过画面宽度的 5%。
- 全过程无裁切，标距、肩部、夹具口边界始终可辨。

构图检查覆盖全过程，不能只检查初始一帧。

### 3.5 场景身份

配置引用以下模板，不把冻结模板改成任意变化参数：

| 配置字段 | 值 |
| --- | --- |
| `scene_spec_version` | `tensile-scene/v0.1` |
| `scene_profile_id` | `metal_flat_dogbone_l1_front_v1` |
| `specimen_template` | `flat_dogbone_v1` |
| `material_profile` | `neutral_brushed_metal_v1` |
| `machine_template` | `dual_grip_machine_l1_v1` |
| `camera_profile` | `front_fixed_v1` |
| `lighting_profile` | `soft_neutral_v1` |
| `background_profile` | `neutral_gray_v1` |
| `tensile_axis` | `Z` |
| `moving_component` / `fixed_component` | `Grip_Upper` / `Grip_Lower` |

## 4. 动画与时间语义

| 时间 | 必须可见的过程 |
| --- | --- |
| 0–1 秒 | 初始静止，试样连续 |
| 1–5 秒 | 均匀轴向拉伸 |
| 5–7 秒 | 标距内部局部变细，颈缩逐渐增强 |
| 7.0 秒 | 首次完全断离 |
| 7–10 秒 | 保持分离，可有轻微回缩或继续分开，不重新接合 |

韧性断裂必须具备可见伸长、局部宽度减小、变形向断裂附近集中和断后间隙。断口位于标距内部，与肩部和夹具根部有明确位置区分。不要求真实应力场、微观断口或材料本构。

**`fracture_time_s` 只表示首次完全断离。** 颈缩开始、裂纹出现但仍有材料连接，均不是该时刻。

固定渲染 Blender 第 1–300 帧，`t=(frame-1)/30`。首次断离对应 Blender 第 211 帧、视频零基索引 210、7.0 秒；Blender 第 210 帧为 6.966667 秒，必须仍连续。以编码后实际帧时间戳验收，误差不超过 `1/fps`。最细连接必须在最终分辨率下可见，不能仅凭数学上宽度非零认定视觉连续。

### 已确认、尚未实施的动态修正

现有版本已在相邻帧间完成断离，但用户认为整体观感偏高分子。下一次原型修正应使最终断离更干脆，同时保留金属韧性断裂的颈缩证据：

- 保留逐渐拉伸和颈缩，允许颈缩末期局部变形适当加速。
- 仍在 7.0 秒首次完全断离，前一帧保持清楚连接。
- 断后少数帧内体现有限、快速的卸载回缩，随后稳定分离；夹持端仍受约束，不表现为大幅橡皮筋式弹跳。
- 颈缩形态和回缩幅度需结合真实金属视频校准，不把一种夸张运动当作所有金属的通用模板。

上述为已确认方向，不是现有 MP4 的已完成特征；具体幅度和时间函数尚未固化，本次文档整理不实施动画修改。

## 5. 视频与标签交付

固定输入见 [configs/synthetic_0001.json](../configs/synthetic_0001.json)：视频 ID 为 `synthetic_0001`，seed 为 `1001`，时长 10 秒、30 FPS、854×480，共 300 帧。场景与标签由同一配置驱动。

正式数据只交付 `outputs/synthetic_0001.mp4` 和 `outputs/synthetic_0001.json`，通过同名配对；不另设供下游构建切片的逐视频 manifest。QA 是单独的检查报告，预览和 `.blend` 是可复现的工程产物。

视频级 JSON 保持以下十字段：

```json
{
  "schema_version": "synthetic-tensile-video/v0.1",
  "video_id": "synthetic_0001",
  "has_fracture": true,
  "fracture_time_s": 7.0,
  "fracture_mechanism": "韧性断裂",
  "fracture_site": "inside_gauge",
  "special_case": null,
  "material_type": "金属",
  "generator_version": "blender-tensile/v0.1",
  "seed": 1001
}
```

机制、位置和特殊情况复用 **tensile-vlm/v4.1** 的原词枚举，禁止同义改写或自建另一套标签。权威来源为相邻数据项目的 `mVllm_2/pipeline/contracts/tensile_vlm_v4_1.json`；当前已核对契约声明 hash 为 `3798f00cbec7a3cad3e50de66dd2b5bdeecca1a95ae74297cbd0d71e7ec438ab`。

该文件是完整视频级源标签，不直接套用帧窗口的四字段 schema。JSON 不加入 `clip_state`、子视频起止时间或路径、采样帧时间、`fracture_start_s` / `fracture_end_s`、训练数据格式或下游可从视频探测的技术信息。子视频与实际采样帧、帧窗口标签和训练 release 由现有数据链路负责。

## 6. 生成、检查与复现

1. 读取本文、实际配置、权威标签契约及数据项目当前处理说明。
2. 使用 Blender MCP 初始化并检查场景；由 Blender Python 创建试样、夹具、局部横梁、材质、背景、灯光和固定相机。
3. 生成初始预览，执行 Scene Gate：对象存在且同轴；标距、肩部、根部可辨；无错误遮挡或穿模；轮廓清楚；构图合规；无无关装饰；修改已固化。
4. 场景通过后加载确定性拉伸、颈缩、断离动画。正式渲染前查看初始、明显颈缩、首次断离和断后四种状态，并额外查看断前相邻帧。当前检查时间为 0、6.5、6.966667、7.0、9.0 秒。
5. 主 Agent 实际查看预览并按项目视觉工作流组织独立复核，修正实质问题后通过 Blender 原生 FFmpeg 渲染完整 MP4。
6. 渲染成功后从同一配置写出 JSON，回读编码后关键画面并执行下表检查。
7. 保存 QA，说明通过、失败、待验证项与限制；本条完成后停止。

MCP 中所有有效调整必须写回脚本或配置，不能只留在 `.blend`。运行命令与文件位置集中维护于 README。

| 验收项 | 判定依据 |
| --- | --- |
| 文件交付 | MP4 与 JSON 均存在、同名；不是仅交场景文件 |
| 媒体可用 | 10 秒、30 FPS、300 帧、854×480；全帧正常解码 |
| 标签正确 | 合法 JSON、十字段完整、枚举合法、与输入一致、断裂时间 7.0 秒 |
| 连续性与时间 | 断前连续，目标帧首次完全断离，编码后时间误差不超过一帧，之后无重接合 |
| 模式与位置 | 有可见颈缩，断口在标距内部；肩部和夹具证据不被遮挡 |
| 全程场景质量 | 夹持关系、固定相机、构图比例和轮廓可见性均满足第 3 节 |
| 可复现 | 相同脚本、配置和 seed 重建后标签、关键几何和时刻一致；明确是否执行完整重复渲染 |
| 下游消费 | 通过真实读取入口验证，不能用“视频可解码、JSON 可解析”替代端到端接入证据 |

QA 汇报应包含 `completed / partial / blocked` 状态、产物路径、目标与实际断裂时间及误差、各验收项结果和已知限制。现有固定 ROI 像素检查只适用于该清晰无遮挡场景，须结合实际画面及几何证据，不是通用断裂分类器。

## 7. 当前实现选择与验证边界

以下描述已交付原型，属于实现记录，不额外冻结未来局部技术细节：

- 使用每帧显式网格及可见性切换，断前一个连通部分、断后两个部分，精确控制时间。
- 肩部用两段半径 0.8W 的相切圆弧，导出跨度约 1.0583W；正交固定相机与约 1.08W 的上夹具总行程满足构图限制。
- 用覆盖全视场的均匀中性背景和固定柔光保持轮廓。运行环境为 Blender 5.2.1 LTS，原生视频输出使用 `image_settings.media_type="VIDEO"` 与 FFmpeg H.264/MPEG4。
- 已交付视频全帧解码通过，首次分离实测 7.0 秒，误差 0 帧；详细数据和文件 hash 只在 QA 报告中维护。

### 下游接入缺口

此前检查数据项目 README、`docs/DATA_PROCESSING_RUNBOOK.md` 和实际源入口时，现役流程读取 `all_videos_tag.csv`、`video_mapping.csv`，并限制源 ID 格式；尚未找到直接读取本项目视频级 JSON 的入口。具体检查版本与证据见 QA。

保留现有交付形式，不生成替代 CSV 或 manifest 来绕过边界；需要确认已有读取入口或另行确定下游支持工作。该缺口不改变视频标签语义，也不能被记为已接入。后续接入前应重新核对数据项目当前说明，不能把这次检查快照视为永久事实。

### 微调有效性边界

当前原型具备连续性、颈缩和位置线索，但“单视频语义清楚”尚不足以证明能改善真实视频识别。用户反馈的金属动态观感需要在扩展训练模板前修正；合成样本不应反复强化固定、夸张的运动特征。微调收益需通过真实视频上的对照评测确认，具体实验设计尚未在本 MVP 中冻结，也未执行训练。
