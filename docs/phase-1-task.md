# Blender 材料拉伸模拟视频生成器：阶段一任务书

## 一、任务目标

使用 Blender MCP 和 Blender Python，完成一条可复现的材料拉伸模拟视频：

- 金属哑铃形或板状拉伸试样；
- 固定于上下夹具之间；
- 经历均匀拉伸、局部颈缩和完全断离；
- 断裂位置位于标距段内部；
- 首次完全断离时刻为 `7.0 s`；
- 输出一条完整 MP4 视频和一个同名 JSON 文件。

本阶段不追求有限元级力学真实性，优先保证：

1. 视觉过程清楚；
2. 标签时间准确；
3. 脚本能够稳定复现；
4. 后续可以参数化扩展。

---

## 二、固定输入配置

建议使用单一配置文件驱动：

```json
{
  "video_id": "synthetic_0001",
  "seed": 1001,

  "duration_s": 10.0,
  "fps": 30,
  "resolution_x": 854,
  "resolution_y": 480,

  "material_type": "金属",
  "has_fracture": true,
  "fracture_time_s": 7.0,
  "fracture_mechanism": "韧性断裂",
  "fracture_site": "inside_gauge",
  "special_case": null
}
```

`fracture_mechanism`、`fracture_site` 和 `special_case`必须使用现有契约原词，禁止自行生成“中部断裂”“延性破坏”等同义标签。当前合法机制、位置和特殊情况枚举已经在 V4.1 契约中冻结。fileciteturn4file0L137-L158

## 三、视频视觉要求

### 1. 场景组成

场景至少包含：

- 上夹具；
- 下夹具；
- 中间试样；
- 正面固定相机；
- 简单中性背景；
- 能够清晰显示试样轮廓的稳定光照。

夹具可以简化，但必须能让人明确理解为拉伸试验场景。

### 2. 时间过程

建议按以下阶段构造：

| 视频时间 | 视觉状态 |
|---|---|
| 0–1 s | 初始静止、试样连续 |
| 1–5 s | 均匀轴向拉伸 |
| 5–7 s | 标距段局部变细、颈缩逐渐增强 |
| 7 s | 首次出现上下两部分完全断离 |
| 7–10 s | 断裂后保持分离，可有轻微回弹或继续分开 |

这里的 `7 s`只有一个含义：

> **视频中首次出现试样完全断离的时刻。**

局部颈缩开始时间不是断裂时间；出现裂纹但仍有材料连接，也不视为已经断裂。

### 3. 韧性断裂最低视觉特征

断裂前应能够看到：

- 试样轴向伸长；
- 标距段局部宽度逐渐减小；
- 变形集中在最终断裂附近；
- 完全断离前存在明显颈缩阶段；
- 断裂后上下两部分具有可见间隙。

不要求模拟真实应力场、断口微观形貌或材料本构关系。

## 四、实现方式

Codex 应采用以下工作方式：

1. 使用 Blender MCP 创建、预览和检查场景；
2. 使用 Blender Python 脚本创建试样、夹具、相机和动画；
3. 使用确定性的关键帧、Shape Key（形态键）、Lattice（晶格变形）或顶点变形实现拉伸和颈缩；
4. 在目标帧实现首次完全断离；
5. 通过 Blender FFmpeg 输出 MP4；
6. 渲染成功后，根据同一输入配置生成同名 JSON；
7. 使用相同配置和 Seed 重新执行时，应得到相同的动画和标签。

MCP 中进行的有效调整必须写回脚本或配置。**禁止只在当前 `.blend` 场景中手工修改而不固化到代码。**

---

## 五、输出要求

每次生成只输出一对正式数据文件：

```text
outputs/
├── synthetic_0001.mp4
└── synthetic_0001.json
```

JSON 内容：

```json
{
  "schema_version": "synthetic-tensile-video/v0.1",
  "video_id": "synthetic_0001",
  "has_fracture": true,
  "fracture_time_s": 7.0,
  "fracture_mechanism": "韧性断裂",
  "fracture_site": "inside_gauge",
  "special_case": null,
  "material_type": "金属",
  "generator_version": "blender-tensile/v0.1",
  "seed": 1001
}
```

JSON 中不要加入：

- `clip_state`；
- 子视频起止时间；
- 子视频路径；
- 采样帧时间；
- `fracture_start_s`或`fracture_end_s`；
- 后续训练数据格式；
- 当前数据处理链路可自动探测的视频技术信息。

后续子视频和帧窗口标签仍由现有数据处理链路统一生成。该项目本身已经以帧窗口证据为中心，并对数据 release、Schema、Fold、Seed 和训练参数执行冻结比较，因此 Blender 端不应复制这套处理逻辑。fileciteturn4file1L13-L17

## 六、自动验收条件

Codex 完成后应自动检查：

1. MP4 和 JSON 均存在，且文件主名一致；
2. 视频可以正常读取；
3. 视频约为10秒、30 FPS、854×480；
4. JSON 是合法对象，必需字段完整；
5. `fracture_time_s=7.0`；
6. 7秒前最后一个可靠画面中试样仍然连续；
7. 7秒对应的首个完全断离画面中已经出现明确间隙；
8. 断裂位置在标距段内部；
9. 断裂前存在可见颈缩；
10. 使用相同配置重新生成时，标签和关键动画时刻不发生漂移。

允许一帧以内的时间误差，即：

```text
|实际首次完全断离时间 - fracture_time_s| <= 1 / fps
```

---

## 七、明确禁止事项

本阶段禁止：

- 批量生成多条视频；
- 实现脆性断裂、界面脱粘或爆炸性断裂；
- 加入相机抖动、严重模糊、遮挡等异常；
- 修改现有视频数据处理链路；
- 直接生成子视频或 V4.1 训练数据；
- 使用随机物理模拟导致断裂时刻不可控；
- 只输出 `.blend` 文件而不输出 MP4；
- 在没有验证首条视频的情况下扩展参数系统。
